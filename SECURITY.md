# Security scope

The optional web UI is loopback-only and must never be exposed publicly. The local stdio server trusts the OS account and MCP client. The separate OAuth HTTP connection server is single-owner: each authorized client accesses the same owner's bank, and tool callers cannot choose another identity. It binds to loopback and can sit behind owner-controlled HTTPS. It is not a multiuser hosted service.

Use a private OS account and data folder. HTTP requires a random pairing secret, OAuth PKCE and resource-bound tokens. The private secret must never be sent through chat, committed or put in a URL. Tokens are bounded and in memory; restart revokes connections. Registration can be exhausted by unauthenticated requests (maximum 32 clients); use reverse-proxy rate limits. Pairing failures are rate-limited. The SDK handles OAuth validation, except a narrow standards-compatible public-client revocation handler using SDK client authentication. Use deployment-level request limits and disable access/query/body logging for authentication and downloads. No provider credentials are bundled.

Generated HTTP download links are bearer capabilities that expire after 15 minutes. Anyone holding a link can download its file until expiry, deletion/replacement or service restart. Configure HTTPS, no-referrer and no-cache; avoid sending links to unintended recipients. The server exposes only generated files, never arbitrary paths or browser profiles. Local stdio file resources depend on client capabilities.

Operator environment configuration can start a subprocess and must not be user-controlled in a hosted system. LinkedIn remains optional and read-only; authenticate in its managed browser yourself. Do not bypass profile locks or copy saved sessions.

Facts returned to a chat provider are subject to that provider's handling, even though the bank is stored locally. Documents and web pages are untrusted data; client instructions direct the model to ignore embedded commands. Backend flags enforce explicit consent and approval but cannot prove the human gave consent: use trusted clients and review model-proposed statements. Exact approved statements are preserved in exports; no model runs inside this server.

Report vulnerabilities privately to the repository maintainer before disclosure. Do not include real resumes, credentials, session files or private exported facts in reports. This repository has no telemetry or hosted data collection. Public HTTPS deployment, account connection and desktop installation need real-client validation before claiming production compatibility.
